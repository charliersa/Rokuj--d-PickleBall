# Google 試算表後台 — 部署說明

## 這套東西怎麼運作

```
手機A ─┐
手機B ─┼─→ Apps Script 網頁應用程式 ─→ Google 試算表（唯一真相）
手機C ─┘         (doGet / doPost)
```

- **試算表是唯一真相**。網頁一開啟就從試算表拉名單與比分，報名／登錄比分直接寫回去。
- **localStorage 退化成離線快取**。沒網路時照樣能用，變更排進待送佇列，連上線按「重試」就補送。
- **分場、賽程、戰績的演算法留在網頁端**（`index.html`）。Apps Script 不重算，而是接收網頁算完的結果，寫進「分場結果／賽程／戰績」三張唯讀報表給你在試算表看。
  > 為什麼這樣切：那套演算法有一百多行細節（性別名額、志願遞補、避免重複搭檔與重複對手、比分合法性判定）。在兩個地方各維護一份，遲早會算出不一樣的分場結果。

## 安裝步驟

### 1. 建立試算表與指令碼

1. 開一份新的 Google 試算表，取個名字（例如「六甲頂匹克球分場系統」）。
2. 選單 **擴充功能 → Apps Script**。
3. 把 `Code.gs` 的全部內容貼進編輯器（蓋掉原本的 `myFunction`）。
4. 存檔（Ctrl+S）。

### 2. 初始化

1. 在 Apps Script 編輯器上方的函式下拉選單選 **`setup`**，按 **執行**。
2. 第一次會要求授權：**審查權限 → 選你的 Google 帳號 → 進階 → 前往「<專案名稱>」(不安全) → 允許**。
   > 「不安全」只是因為這個指令碼沒經過 Google 審核。它只會動你自己這份試算表。
3. 成功後回到試算表，應該多出 7 張工作表：
   `設定`、`報名`、`比分`、`分場結果`、`賽程`、`戰績`、`紀錄`。

### 3. 設定管理密碼 ⚠ 必做

到 **`設定`** 工作表，把 `管理密碼` 那一列的「值」填上一組只有你知道的字串。

**密碼留空的話，所有管理動作都會被拒絕**（這是刻意的，避免你以為有保護但其實沒有）。

也可以用試算表選單 **匹克球系統 → 產生一組新的管理密碼** 自動產生。

| 設定項目 | 說明 |
|---|---|
| 管理密碼 | 清空名單、刪別人、登錄比分、改首發日期、推送報表時要輸入 |
| 首發開打日期 | `YYYY-MM-DD`。網頁的場次清單從這天之後的第一個週五起算 8 週 |
| 雙打場人數上限 | 1、2、3、5 號雙打場每場最多幾人（4–8）。4 號主題場固定 8 人 |
| 雙打場局數 | 1、2、3、5 號場各排幾局（120 分鐘 ÷ 每局 15 分鐘 = 8） |
| 開放場地 | 有開的場地號碼，逗號分隔（例如 `1,2,4`）。網頁管理選單的「開放場地」按鈕會自動寫入 |
| 關閉報名場次 | 不開放球友報名的日期，逗號分隔。網頁管理選單的「開放報名日期」按鈕會自動寫入 |
| 女雙PK場次 | 第二週 4 號場採「玩法 B 閨蜜 PK 賽」的日期，逗號分隔。網頁的切換按鈕會自動寫入 |
| 允許球友自行報名 | `TRUE` = 拿到連結的人可自己報名；`FALSE` = 連報名都要密碼 |
| 紀錄保留筆數 | `紀錄` 工作表超過這個筆數就自動刪掉最舊的 |
| 試算表配色 | `light`（淺色，推薦）或 `dark`（深色，跟網頁同色）。改完要執行選單的「重新套用美編」 |

### 4. 部署成網頁應用程式

1. 編輯器右上 **部署 → 新增部署作業**。
2. 類型齒輪 → **網頁應用程式**。
3. 設定成：
   - **執行身分：我**（這樣球友不需要 Google 帳號）
   - **誰可以存取：任何人** ← 一定要選這個，不是「任何擁有 Google 帳戶的人」
4. 按 **部署**，複製那串 **`https://script.google.com/macros/s/.../exec`**。

先把網址直接貼到瀏覽器開一次，應該看到類似：

```json
{"ok":true,"version":"1.0.0","action":"ping","spreadsheet":"六甲頂匹克球分場系統",...,"hasPassword":true,...}
```

看到 `"hasPassword":true` 就表示密碼有設到。如果看到 HTML 登入頁面，就是第 3 步的「誰可以存取」沒設成「任何人」。

### 5. 把網址接到網頁

打開 `index.html`，找到檔案上方這一行（約第 340 行）：

```js
const API_URL = '';
```

把網址貼進去：

```js
const API_URL = 'https://script.google.com/macros/s/AKfycb..../exec';
```

> **留空就是純離線模式**，行為跟加後台之前完全一樣。所以貼錯或還沒部署完，頁面也不會壞掉。

### 6. 修改程式之後要重新部署

改了 `Code.gs` 一定要 **部署 → 管理部署作業 → 鉛筆圖示 → 版本選「新版本」→ 部署**。
網址不會變。**只按存檔是不會生效的**，這是最常見的卡關點。

## 權限模型

| 動作 | 需要密碼？ |
|---|---|
| 看名單、分場、賽程、戰績 | ❌ |
| 自己報名 | ❌（除非把「允許球友自行報名」改成 FALSE） |
| 取消**自己這支手機**報的名 | ❌ |
| 取消**別人**的報名 | ✅ |
| 登錄比分 | ✅ |
| 清空名單、載入範例、沿用上週名單 | ✅ |
| 改首發開打日期 | ✅ |
| 切換第二週女雙玩法（A 旋轉搭檔／B 閨蜜 PK） | ✅ |
| 設定開放場地 | ✅ |
| 設定開放報名日期（關閉的日期仍可由管理員代報名） | ✅ |
| 推送報表到試算表 | ✅ |

網頁會在你第一次碰到管理動作時跳出密碼框，**解鎖一次就記在那支手機上**，不用每次輸入。在「報名」頁最下面可以登出管理權。

### 關於「自己這支手機」

報名時會連帶記下一個隨機的裝置代號（存在那支手機的 localStorage），伺服器用它判斷「這筆是不是你報的」。這讓球友可以自己改掉填錯的報名，不用每次找你。

**但它不是身分認證** — 它只防手滑，不防有心人。真正的管理權限只看密碼。

### 這套安全性的實際強度

網址等於通行證：拿到網址的人可以讀全部資料、也可以報名。對 LINE 群內的固定團這樣剛好；**但不要放任何你不想讓全群看到的東西**（真實姓名以外的個資、電話等等）。

如果連報名都想管起來，把「允許球友自行報名」改成 `FALSE`，那就變成只有你一個人能操作。

## 日常使用

**開團前**：在網頁按「沿用上週名單」或讓球友自己報名。名單即時同步到試算表，你隨時可以在手機或電腦上看。

**打球當天**：在「賽程」頁登錄比分。每格停手約 0.7 秒後才送出（不會每打一個字就連線一次）。

**打完**：在「分場」頁按 **推送分場／賽程／戰績到試算表**，三張報表就會更新成這一場的最終結果。

**要貼 LINE**：照舊用「複製分場結果」「複製 X 號場賽程」，那是純文字，跟後台無關。

## 常見狀況

| 症狀 | 原因與處理 |
|---|---|
| 網頁一直顯示「跟試算表連線失敗」 | 把 `API_URL` 貼到瀏覽器開一次。看到 JSON 就是網址對；看到登入頁就是「誰可以存取」沒設成「任何人」 |
| 「試算表回傳的不是 JSON」 | 同上，部署權限問題 |
| 「管理密碼不正確」 | `設定` 工作表的密碼跟輸入的不一致。注意前後空白 |
| 「管理密碼還是空的」 | 第 3 步沒做 |
| 改了 Code.gs 但沒反應 | 沒重新部署（見第 6 步） |
| 「另一個人正在寫入」 | 兩人同時操作，等幾秒再按一次。這是正常的鎖等待 |
| 「找不到『報名』工作表」 | 沒執行 `setup()`，或工作表被改名 |
| 分場順序怪怪的 | 分場依報名先後，而報名順序是看 `id` 欄。不要去改 `報名` 工作表的 `id` |
| 報表裡的日期變成 `2026/10/2` 格式 | 欄位格式被動過。執行 **匹克球系統 → 重新套用美編** 修回純文字 |
| 表格看起來跑掉了／欄寬亂了 | 執行 **匹克球系統 → 重新套用美編** |
| 在報表上打字跳出警告 | 正常的，三張報表是唯讀的。真要改就按「仍要編輯」，但下次推送會被覆蓋 |

## 試算表選單

初始化後，試算表會多一個 **匹克球系統** 選單：

- **初始化／重新套用格式** — 補缺的工作表與設定，然後套用美編（可重複執行，不會洗掉已填的設定）
- **重新套用美編** — 只重跑排版與配色。手改過格式想復原、或換了配色之後執行這個
- **切換深色／淺色配色** — 一鍵在兩套配色間切換並立即套用
- **產生一組新的管理密碼** — 隨機產生並寫入（已解鎖的手機下次操作要重新輸入）
- **清空所有報表快照** — 清掉三張唯讀報表（報名與比分不受影響）
- **系統狀態** — 看版本、時區、密碼有沒有設、各表筆數

## 美編（排版與配色）

`setup()` 會自動套用，之後任何時候都能用選單的 **重新套用美編** 重跑。可以重複執行，規則不會越疊越多。

**兩套配色**，用「設定」工作表的 `試算表配色` 切換：

- **`light`（預設）** — 標題用網頁的深藍＋螢光綠維持品牌感，內容區留白好讀。推薦，因為試算表自己的工具列、列號、選取框都是亮的，而且列印不吃墨。
- **`dark`** — 跟 `index.html` 同一組色票。看起來最有一致性，但會跟試算表本身的亮色介面打架。

**做了哪些事**

| 項目 | 內容 |
|---|---|
| 版面 | 關閉格線、凍結標題列、固定欄寬、標題列加粗並壓上螢光綠底線 |
| 斑馬紋 | 只套用在**有資料**的列（用公式判斷），不會在空白區鋪滿條紋 |
| 場地色塊 | `1`～`5` 號場做成色塊，跟網頁上的場地顏色一致（舊資料的 A/B/C 依序視為 1/2/4 號場） |
| 性別 | `M`／`男` 藍、`F`／`女` 粉，跟網頁一致 |
| DUPR | 3.0 以上標紅加粗（排得進 1 號場的門檻），固定一位小數 |
| 賽程狀態 | 完賽＝綠、未登錄＝灰、比分不合法＝紅 |
| 戰績 | 第 1 名整列鍍金；淨分正數綠、負數紅，自動帶 ± 號 |
| 紀錄 | `FAIL` 標紅，其餘壓灰 |
| 下拉選單 | 性別 `M/F`、志願 `auto/1/2/3/4/5`、允許報名 `TRUE/FALSE`、配色 `light/dark` |
| 分頁顏色 | 報名／比分用螢光綠，三張報表用各自的場地色，設定與紀錄壓灰 |
| 保護 | 三張報表加「僅警告」保護：手滑打字會跳提醒，但不會真的鎖住你 |
| 等寬字 | 對戰代號、裝置代號、時間用等寬字，長字串好對齊掃讀 |
| 密碼提醒 | `管理密碼` 留空時，那一列會變紅底提醒 |

**注意**：美編會把你手動改過的格式蓋掉（這就是它的用途）。如果你在某欄加了自己的色彩標記，執行「重新套用美編」會消失。`紀錄` 以外的工作表都不建議手改格式。

## 注意事項

- **`分場結果`／`賽程`／`戰績` 三張表不要手改**，每次推送都整場覆蓋。
- **`報名` 表的 `id` 欄不要改**，分場順位看它。姓名、DUPR、志願可以直接在試算表改，網頁重新整理就會讀到。
- `load` 一次回傳**所有**場次的名單與比分。一年約 50 場 × 24 人 ≈ 1200 列，這個量沒問題；真的累積太多年再把舊場次剪到另一份試算表存檔。
- 時區跟著試算表走（檔案 → 設定 → 時區），紀錄的時間戳與日期判斷都用它。

## 從 A/B/C 三場升級到 1～5 號場（v1.1.0）

1. 把新版 `Code.gs` 整份貼進 Apps Script 編輯器並存檔。
2. 執行一次 **`setup()`**：會把「A/B場人數上限／A/B場局數」改名成「雙打場人數上限／雙打場局數」（值保留），並補上「女雙PK場次」。
3. **部署 → 管理部署作業 → 鉛筆 → 新版本 → 部署**（網址不變）。

舊資料不用手改：`報名` 表裡的志願 `A/B/C` 會自動當成 `1/2/4` 號場讀取，舊比分也會自動對應到新場號。
